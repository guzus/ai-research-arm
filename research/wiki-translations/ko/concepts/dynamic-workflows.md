**동적 워크플로(Dynamic Workflows)**는 [[anthropic|Anthropic]]이 [[claude-opus-4-8]]과 함께 2026-05-28에 출시한 Claude Code 기능이다. 작동 방식이 독특하다. **Claude가 하위 에이전트를 조율하는 JavaScript 스크립트를 작성**하고, Claude가 직접 나서는 대신 이 스크립트가 분산 실행을 주도한다. 실행마다 **병렬 에이전트 1,000개로 제한**되며(ARA digest 2026-05-30), **기존 테스트 모음을 병합 기준으로 삼아 수십만 LOC 규모 코드베이스를 마이그레이션**하는 용도로 명시적으로 제시됐다. **Enterprise / Team / Max** 등급에만 제공된다.

## 중요한 이유

- **"완료될 때까지 에이전트를 실행"하는 구체적인 답.** 동적 워크플로는 Anthropic이 **목표를 달성할 때까지 에이전트가 반복 실행되는** 범주에 내놓은 가장 구체적인 기능으로 보인다. [[cognition-ai|Cognition Devin]](제작사는 이제 자체 코드의 89%를 Devin으로 작성) 및 OpenAI Codex Goal Mode와 경쟁한다(ARA digest 2026-05-29).
- **비용의 초점이 분산 실행으로 이동한다.** 수백 개의 하위 에이전트로 분산되는 세션에서는 비용 논의가 단일 대화가 아니라 **하위 에이전트별 토큰 지출**과 부모 오케스트레이션 오버헤드에 집중된다. 같은 릴리스에서 **Opus 4.8 Fast mode 가격을 3× 낮췄고**, 이 수단이 분산 실행의 경제성을 유지한다.
- **동반 기능도 같은 시기에 출시됐다.** claude.ai의 노력 수준 제어(사용자 측 컴퓨팅 예산 조절 기능)와 **Messages API를 통한 작업 중간 시스템 프롬프트 주입**이 동적 워크플로와 함께 출시됐다. 이를 합치면 컨텍스트를 다시 시작하지 않고도 여러 턴 세션을 편집 가능한 에이전트 루프로 만들 수 있다(ARA digest 2026-05-29).
- **커뮤니티 반응.** 별도 HN 스레드는 2026-05-30 이월 집계 기준 **150 pts / 117 comments**를 기록했다. **하위 에이전트 1,000개 제한** 자체가 비용 통제와 피해 반경 논의의 초점이 됐다. [[agentic-ai-security]]가 대규모 분산 실행 에이전트 시스템을 지배할 것으로 예측한 바로 그 실패 형태다.
- **Claude Code에 세션 간 메시징과 분류기 기반 기본값 추가(2026-08-07).** 이제 세션끼리 **메시지를 보낼 수 있다**. 한 세션이 **기록이나 파일이 아닌 요약**을 보내면 다른 세션이 **어느 기기에서든 작업 도중에** 이를 받는다. [[zawinskis-law-of-multiagents]]가 업계의 수렴점으로 지목한 임의의 스레드 간 조율을 제품화한 형태다. 같은 시기에 다음 기능도 나왔다. **Pro/Max/Team의 기본 권한 경로가 된 "auto mode"**(별도 분류기가 셸 명령·동작을 검토하며, Anthropic 테스트에서 수동 승인 방식의 14%에 비해 위험한 명령의 **89%**를 포착한 것으로 전해짐), **세션 예산**, 자동 **저장소 스킬 로딩**, 세션 중간에 호출할 수 있는 **"advisor" 모델**이다. 분류기 기본값은 이 문서의 피해 반경 미해결 질문에 대한 직접적인 답이다. [[agentic-ai-security]]를 참고하라(Latent.Space AINews; ARA daily digest 2026-08-09).

## 미해결 질문

- **피해 반경.** 실제 코드베이스에서 수백 개의 병렬 하위 에이전트를 실행하면 단일 채팅 세션보다 훨씬 넓은 파괴 가능 영역이 생긴다. [[agentic-ai-security]]가 추적하는 것과 같은 실패 영역이다. 어떤 보호 장치가 기본 제공되고 어떤 책임이 사용자에게 넘어가는가?
- **모델 성능보다 메모리 정책이 더 중요할 수 있다.** [[agent-lifespan-engineering]]은 하위 에이전트의 반감기가 자식이 호출하는 Claude 모델이 아니라 부모의 메모리 정책에 의해 결정된다고 예측한다.
- **조율 비용.** 병렬화로 얻는 절감분 가운데 부모 세션의 오케스트레이션·충돌 해결 오버헤드로 소모되는 비중은 얼마나 되는가?
- **등급 제한의 경제성.** Enterprise / Team / Max 전용이다. 고가 등급 기능으로 남을까, 아니면 경쟁사(Devin / Goal Mode)가 더 낮은 등급에서 비슷한 분산 실행을 제공하면서 아래로 내려올까?
