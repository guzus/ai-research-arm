## Highlights (Top 5 Must-Read)

### 1. Athanor: An Agent-Native System for Autonomous Post-Training Research
**Authors**: Yufa Zhou, Yichen Wang, Jiakun Fan, Ziqi Shu, Zhichao Liu, Anru R. Zhang, Neiwen Ling, Zijun Wei
**arXiv**: [2610.21055](https://arxiv.org/abs/2610.21055)
**TL;DR**: Friday's Self-Improvement Problem said no terminating gate is both reliable and non-conservative. Athanor measures a weaker RSI that can be scored today: frontier agents post-training a raw base model on public data, no teacher models, real GPUs. Four Claude Opus 5.5 agents, 104 hours, eight GPUs each. Qwen3-4B-Base goes 15.9→67.3 on the six-task dev suite and 9.2→48.2 held-out — matching official Qwen3-4B-Instruct-2507 (66.5 / 47.9). The record is SFT on public reasoning data, an RL rollout change one agent introduced, cross-agent weight merges, and self-distillation.
**Why it matters**: Tuesday's RSI-Anything wanted a world-model filter; Friday's Minecraft run proved a long coding loop can finish. This is the first public campaign where a team of frontier agents autonomously post-trains a raw base into a cross-domain generalist that matches the lab's own instruct model.

### 2. Evolving Together, Failing Apart: The Skill-Policy Co-evolution Trap
**Authors**: Yujie Feng, Xiaobin Wang, Jinluan Yang, Xiaonan Shi, Pengjun Xie, Philip S. Yu, Xiaoming Wu, Jieping Ye
**arXiv**: [2610.20845](https://arxiv.org/abs/2610.20845)
**TL;DR**: Skill-policy co-evolution reports the policy's score on the bank it trained with. After deployment the bank keeps changing while the policy does not. Cooperative acceptance — keep a skill only if it helps the current policy — puts the delivered pair at a peak over candidate banks, so any rewrite is predicted not to help. Across four methods and five benches, worst-case success under skill drift sits 5–13 points below that peak and erases 52–93% of the delivered bank's gain over the no-skill baseline. CODA adds worst-case success, consistency under meaning-preserving edits, and resistance to corrupted skills.
**Why it matters**: Friday's leftover RSI papers optimized the pair. This one shows the evaluation is scoring a pairing that will not be there at deployment.

### 3. OS-Helix: Unifying GUI Interaction and Code Execution in Native Computer-Using Agents
**Authors**: Bowen Yang, Kaiming Jin, Zichen Ding, Zhenyu Wu, Zehao Li, Qiushi Sun, Yu Qiao et al.
**arXiv**: [2610.22234](https://arxiv.org/abs/2610.22234)
**TL;DR**: Friday's OpenGCUA shipped an open generalist computer-use stack. OS-Helix asks how GUI and code share one action space. Prompting a GUI agent with a code tool *hurts* (Qwen3-VL-32B ~34%→~32% on OSWorld-Verified). They train the routing: application-artifact Ubuntu states, decoupled instruction/evaluator synthesis, SFT on filtered hybrid traces, then Step-balanced GSPO so long code actions do not dominate the RL gradient. OS-Helix-27B-RL reaches 66.44% on OSWorld-Verified (+42.9% over the matched Qwen3.5 hybrid); 27B / 35B-A3B already +35.0% / +33.7% before RL. ~31K successful hybrid SFT traces to be released.
**Why it matters**: Computer-use is not a tool list. GUI/code routing has to be in the weights, and the RL objective has to count steps, not tokens.

### 4. Close Enough is Nowhere Near: Fidelity-Consumability Decoupling in KV Caches
**Authors**: Adam Deng, Shicheng Liu, Yada Zhu
**arXiv**: [2610.22016](https://arxiv.org/abs/2610.22016)
**TL;DR**: Multi-agent systems talk in text and throw away the reading. The appealing fix is to hand the sender's KV cache to a frozen reader. Eight substitution methods all sit at the uninformative-cache floor (0.180 vs native 0.665 on a SQuAD probe). Geometric similarity does not predict whether the reader can use the cache; corrupting one layer is as bad as corrupting all 28. Competitive attention: keys compete, so a displacement too small to show up in a norm changes which tokens win. What works is keeping the reader's own cache and attending over the sender's as extra context, adapting only queries.
**Why it matters**: Faithful cache substitution is the wrong target. The reader's tolerable set is not a ball in cache space. Add, do not replace.

### 5. Can Capability Enhancement be Localized?
**Authors**: Anh Tuan Nguyen, Anna Bair, Zico Kolter
**arXiv**: [2610.21294](https://arxiv.org/abs/2610.21294)
**TL;DR**: Friday's Adversarial Parameter Decomposition asked how weights compute. This CMU paper asks the complementary pruning question: given a model and a task, is there a *small* set of heads whose removal *raises* accuracy, with no fine-tuning? A two-stage screen finds such combinations across families. In a simplified multi-head softmax model with two conflicting-feature tasks, gradient descent from small init provably concentrates the conflict into particular heads; ablating them helps one task and hurts the other even though training reached a global optimum of the joint objective.
**Why it matters**: If a jointly trained optimum still hides heads that are net-negative for a task, "important heads" is not the same object as "heads you should keep."
