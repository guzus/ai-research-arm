## Highlights (Top 5 Must-Read)

### 1. Counterfactual World Models: JEPAs That Reason About "What If"
**Authors**: Randall Balestriero, Yann LeCun, Kerda Varaku
**arXiv**: https://arxiv.org/abs/2611.24778
**TL;DR**: World models trained only on factual transitions cannot answer “what would have happened under a different action, same hidden disturbance?” — no amount of data or capacity closes that on its own. When actions and disturbances act as separate forces, the counterfactual is, to first order, the observed outcome plus the difference of the world model’s two predictions. Same JEPAs, no extra parameters or retraining: counterfactual R² rises from 38–46% to 86–96% on four simulators; hindsight planning finds the goal-reaching action in 35–69% of events vs 14–23% for an oracle that knows the simulator but not the outcome.
**Why it matters**: It turns “what if” into a property of the dynamics, not a new training objective — and it works from pixels on frozen DINOv2/v3, SigLIP 2, CLIP and EVA-02.

### 2. General progress substitutes for specific training data in language models
**Authors**: Mark Marosi, Peter Antal
**arXiv**: https://arxiv.org/abs/2611.24844
**TL;DR**: Withholding a skill’s training signal (chess check-responses, a programming language in a 7B web-text model, Othello, molecular strings) delays the capability, and the delay in larger models is predicted from smaller ones. Once the rest of training has progressed, the withheld skill is acquired with a small — and shrinking — fraction of the data needed from initialization; a control rule of equal difficulty is learned much more slowly. A chess model never trained to answer check still ranks legal replies almost as well as one that was.
**Why it matters**: Data filtering buys time, not a permanent lock; general progress substitutes for the missing examples, so the data needed to regain a withheld capability falls as models improve.

### 3. Training Language Models for Introspective Oversight
**Authors**: Alex Lin Wang, Linus Yifeng Tang, Dami Choi, Neil Chowdhury
**arXiv**: https://arxiv.org/abs/2611.23365
**TL;DR**: Reward hacking, deception and sycophancy are hard to see in transcripts; asking the assistant is unreliable because it was not trained to report on itself. Transluce + Thinking Machines Lab add a third-person observer role that shares the assistant’s weights but is trained only for accuracy against verified behavior. On five held-out oversight evals, an observer on Qwen3.6-27B reaches mean AUROC 0.907 vs honesty training 0.864, transcript monitoring 0.828 and activation oracles 0.796. Training the observer also makes every baseline work better on the fine-tuned assistant.
**Why it matters**: Oversight that can see the full computation, not just the transcript, is trainable — and it makes the model easier for *other* monitors to read.

### 4. Toaster: Nonlinear Memory from Cascaded Linear Memories and Target Propagation
**Authors**: Zeman Li, Ali Behrouz, Yuan Deng, Praneeth Kacham, Rami Al-Rfou, Meisam Razaviyayn, Vahab Mirrokni
**arXiv**: https://arxiv.org/abs/2611.23648
**TL;DR**: Linear memories (DeltaNet, KDA) train fast because a chunk of delta-rule steps has a WY form; deep memories (TTT-MLP, Titans) can represent maps no matrix can, but they don’t. Toaster stacks two linear memories with an activation, uses target propagation so each layer still runs on an unmodified delta-rule kernel, and updates the hidden memory once per chunk. At matched 0.2B–1.6B backbones it beats KDA on C4 and PG19, matches or beats attention, and at 1.2B beats Titans. A 3:1 hybrid is 0.18/0.44 perplexity below the attention baseline; at 32K context it is 2.8–5.5× faster than the tested Titans configs.
**Why it matters**: Nonlinear recurrent state no longer has to give up the fast linear-memory kernel — Google’s Titans follow-up that actually trains like DeltaNet.

### 5. Think Offline, Act in Real Time: Self-Improving Visual Game Agents through Code
**Authors**: Zipeng Qiu, Shusheng Xu, Jiale Li, Yukun Zhou, Chenyue Li, Wenshuang Li, Tongkai Yang, Binhang Yuan
**arXiv**: https://arxiv.org/abs/2611.24590
**TL;DR**: On an unfamiliar real-time visual game the screen keeps moving while the agent thinks. A 2B controller with real-time chunking (committed actions fire while it reasons) is one policy; a model that writes, tests and revises a program between attempts is the other. Across 170 GameWorld tasks, ≤8 one-minute executions, code-as-policy reaches 47.80% mean progress vs 30.90% for the trained controller and leads all five game categories. Updating the controller’s weights on a single game barely helps.
**Why it matters**: For real-time visual play, the durable self-improve artifact is a program written offline, not a weight update made during the episode.
