## Highlights (Top 5 Must-Read)

### 1. VR-SparseQuant: Accurate FP4 Quantization with 2:4 Sparsity on Vera Rubin
**Authors**: Samir Khaki, Wei-Chen Wang, Song Han, Ryan Hanrui Wang
**arXiv**: https://arxiv.org/abs/2611.25717
**TL;DR**: NVIDIA Vera Rubin’s native format is E2M1 FP4 with UE5M3 block scaling (`VRFP4`). Dense W4A4 still wrecks quality; VR-SparseQuant uses Rubin’s elementwise 2:4 sparsity so two sparse streams share the same FP4 value budget and spend it on the activations with the largest errors. Offline scale-ratio calibration avoids a runtime search. On Nemotron-3-Nano-30B-A3B, WikiText-2 PPL falls 6.85 → 5.57 vs dense RTN W4A4; native Rubin kernels hit 3.1× GEMM and 2.7× MoE vs BF16.
**Why it matters**: First adaptive activation recipe that actually uses Rubin’s sparse FP4 instructions, not a paper format the silicon will not run.

### 2. Tether: Verified Stateful Policy Engine for System-Level Monitoring of Agents
**Authors**: Meghana Aparna Sistla, Alaia Solko-Breslin, Somesh Jha, Aditya Kanade, Krishnamurthy Dj Dvijotham
**arXiv**: https://arxiv.org/abs/2611.25599
**TL;DR**: LLM monitors are unprovable; stateless policy layers miss multi-step flows (a Python script’s network call is invisible to a command allowlist). Tether runs each proposed action in an ephemeral sandbox, infers semantics from syscalls, and enforces *stateful* policies written in a Lean 4 DSL — e.g. “no network after reading a secret file,” with the invariant proved. One policy across coding-agent benches blocks 100% of in-scope attacks at <5% benign false-positive rate.
**Why it matters**: Agent safety that sits below the model, on observed side-effects, with a proof rather than another judge prompt.

### 3. WeightCode: Installing New Capabilities into Neural Networks via Weight-Space Programming
**Authors**: Bo Li, Taoyong Cui, Bob Zhang, Mengran Li, Chengyang Zhang, Yang Zhang, Pheng Ann Heng, Wanli Ouyang, Zhenfei Yin, Yingcheng Wu, Ling Yang
**arXiv**: https://arxiv.org/abs/2611.25476
**TL;DR**: A frozen language model writes executable programs that *read, construct, or patch weights directly* — no gradient step. Once installed, the new skill runs without the LLM. Given a grammar or eight demos, previously unseen command compositions go 0% → 99.8% exact match and a new pickup action 0% → 98.4%, while original skills stay. On ImageNet, four programs beat eight matched fine-tunes by 8.84–17.62 points; stacking six more programs on an already-edited net adds 5.23–14.50 contrast-robustness points on top of a prior noise gain.
**Why it matters**: Capabilities as reusable weight programs, not another LoRA — and they accumulate instead of overwriting.

### 4. How Feedback-Free Self-Evolution Reshapes Agent Skills
**Authors**: Litao Guo, Man Chen, Xinli Xu, Jinsong Zhou, Zixin Zhang, Ying-Cong Chen
**arXiv**: https://arxiv.org/abs/2611.25534
**TL;DR**: Agent “skills” are expert procedure docs that models now rewrite with no task, run, or judge. Every tested model gets *worse* with the rewritten skills — 15 points on SkillsBench after 30 rounds. Rewriting pulls text toward the model’s own prior and drops the knowledge the model would not write unaided; putting that knowledge back recovers most of the loss. SkillDiff marks it in place and gains +4.8 points without changing the skill’s wording or adding feedback.
**Why it matters**: Unsupervised skill self-edit is not RSI; it is prior collapse, and the valuable part of an expert skill is exactly what the model will not invent.

### 5. PosteriorBench: Evaluating Behavior Posterior Sampling in Language Models
**Authors**: Zhiyang Xun, Daniel D. Johnson, Sarah Schwettmann, Neil Chowdhury (Transluce)
**arXiv**: https://arxiv.org/abs/2611.25735
**TL;DR**: Rare behaviors are hard to study because ordinary sampling barely ever hits them. PosteriorBench asks for cheap samples from the *model’s own posterior* over transcripts that exhibit a named behavior. 21 tasks on Qwen3.5-0.8B, probabilities \(10^{-5}\)–\(10^{-1}\), exact posteriors from a billion labeled responses. Prompting is cheap but plateaus at high KL; fine-tuning on posterior samples is often cost-prohibitive; several published trainers do no better. No evaluated method is both efficient and faithful.
**Why it matters**: A clean, expensive-to-fake yardstick for “show me the model’s rare mode,” not another capability leaderboard.
