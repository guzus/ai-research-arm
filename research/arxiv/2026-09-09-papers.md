## Highlights (Top 5 Must-Read)

### 1. Hyperparameter Scaling Laws Across MoE Sparsity
**Authors**: Changxin Tian, Kunlong Chen, Jia Liu, Ziqi Liu, Zhiqiang Zhang, Jun Zhou
**arXiv**: [2609.08690](https://arxiv.org/abs/2609.08690)
**TL;DR**: Conventional HP transfer fails once MoEs get ultra-sparse: optimal LR and batch size move with activation ratio, and neither total nor activated parameter count explains the shift. 1,800 pre-training runs (six activated-parameter scales, up to 6B non-embedding, ~20T tokens, 200k H800-hours) isolate two regimes. At fixed sparsity, optimal batch size is a power of tokens \(D\); optimal LR scales with compute \(C\) and is robust to the \(N\)–\(D\) split. Across sparsity, the activation ratio \(A\) enters both laws as an extra multiplicative power. Predicted HPs stay near the observed optimum on a held-out 12B MoE that activates 1/64 of its experts.
**Why it matters**: Sparse-MoE training recipes cannot be copied from dense or dense-equivalent laws — sparsity is its own scaling axis.

### 2. ExecCritic: Learn to Test, Test to Improve for Coding Agents
**Authors**: Leitian Tao, Baolin Peng, … Sharon Li, Jianfeng Gao
**arXiv**: [2609.09133](https://arxiv.org/abs/2609.09133)
**TL;DR**: Execution feedback only helps if the tests encode the issue. When the same trajectory writes the patch *and* the test, their errors agree and the agent gets false confidence. ExecCritic splits the job: a Test agent writes repository-native tests, a fail-closed harness freezes them, and a Repair agent may change source only. Holding Repair fixed, base-agent tests drop SWE-bench Verified from a no-test 61.2% to 57.3%; GPT-5.6-sol tests raise it to 65.3%. Role-specific RL on Qwen-3.5-35B-A3B lifts Test Base-to-Gold from 22.2% to 62.2%; the two post-trained Qwen agents together reach 72.6% with no stronger-model feedback at eval.
**Why it matters**: For coding agents, test quality is not a side channel — it decides whether execution feedback helps or hurts.

### 3. API Benchmark Scores Do Not Reliably Transfer to Chatbot Interfaces
**Authors**: Jennifer Wang, Joachim Baumann, Daniel E. Ho, Sanmi Koyejo
**arXiv**: [2609.08861](https://arxiv.org/abs/2609.08861)
**TL;DR**: Release-day benches are API numbers. ChatGPT, Claude, and Gemini were audited across seven systems and nine benches (capability, social bias, sycophancy). API evals score +3.4 pp accuracy and +2.1 pp test–retest agreement versus the matching chatbot UI. For ChatGPT, the API–interface gap exceeds the API-only gap between GPT 5.3 and GPT 5.4. Sweeping system prompts, sampling, and reasoning settings moves some cells and does not close the gap.
**Why it matters**: An API score is not a measurement of the product people actually talk to.

### 4. Silent Revision: Measuring Undisclosed Change in the Safety Frameworks of Frontier AI Developers
**Authors**: Louis Yiven Zhu
**arXiv**: [2609.08789](https://arxiv.org/abs/2609.08789)
**TL;DR**: The EU and California treat published safety frameworks as accountability instruments and already require revision — but not a *legible* one. Across every public version from the twelve developers that have one, 710 commitment instances and 244 adjudicated changes: 67% of material edits are silent under a strict standard (53% lenient). 77% weaken or remove a commitment; weakenings are more often silent than strengthenings. Narrative announcements run 74% silent vs 63% for itemised changelogs. One provider already publishes an incomplete enumeration.
**Why it matters**: A justification says why the framework changed. Only an enumeration makes the change auditable.

### 5. SyncWorld: Visual Calibration Enables World Models as Zero-Shot Simulators
**Authors**: Yuncong Yang, Zhengtao Han, … Yilun Du, Chuang Gan
**arXiv**: [2609.09155](https://arxiv.org/abs/2609.09155)
**TL;DR**: The same numerical action is not the same visual event once camera, placement, or embodiment changes, so mixed-embodiment world models get conflicting supervision. SyncWorld conditions on a short visual calibration episode — paired frames and actions that expose every controllable DoF — and reads the setup-specific Action–Visual Mapping in context. Trained that way, it simulates unseen environments with no extra training, and the rollouts support test-time policy improvement without a gradient step.
**Why it matters**: Actions become a language the world model can interpret from a few in-context demos, instead of a coordinate system that has to be retrained per robot.
