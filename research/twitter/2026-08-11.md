That objection has force on enforcement but not on the record, since the Code of Practice signatures and OpenAI's own support-page language are the labs' documents rather than inference. A sharper technical objection also stands unanswered: a watermark robust enough to survive editing cannot be output-neutral, and nobody has said what happens when the model emits code, where token choice is semantically load-bearing. Treat OpenAI's position as stated intent, not shipped capability.</p>

      <p><strong>Counter / contradicting:</strong> The chosen example undercuts the claim. Distributional text watermarks work by biasing token sampling wherever the model's output distribution has entropy to spare; where the next token is nearly determined, there is nothing to bias. Source code, quotations and short structured text are the canonical low-entropy cases — so "check if a PR was generated by Claude Code" names the artifact class the technique marks least reliably. @DeveloperAlly set out the standard failure set the same evening: paraphrasing through a second model degrades the signal, the scheme is reverse-engineerable in both directions (scrubbing a real mark, or spoofing one onto harmful content to frame a lab), low-entropy text cannot carry a mark, and detection has non-trivial cost. None of that makes the watermark useless — a signal that survives casual copy-paste is worth having, and the earlier round of "removal" claims came from parties selling removal tools rather than from measurement. But the honest position is that this is a provenance hint at population scale, not per-document attribution, and the detection API is the artifact that will make that difference legible.</p>
