Gemini 3.5 Flash의 네이티브 컴퓨터 사용: 구글의 저가 티어 에이전틱 제어 승부수

구글이 프리미엄 기능을 Flash 티어 가격의 기본 기능으로 바꾼 방식 — 그리고 안전성 대 처리량 트레이드오프가 에이전틱 AI 시장에 갖는 의미.

6월 24일, 2026년, 구글은 가장 빠르고 저렴한 모델 티어인 Gemini 3.5 Flash에 "네이티브" 컴퓨터 사용을 내장 도구로 탑재하고 표준 API 가격 대비 추가 프리미엄을 붙이지 않음으로써 컴퓨터 사용 에이전트 시장을 뒤집어 놓았다 1. 이는 컴퓨터 사용을 가장 비싼 모델 뒤에 가둔 프리미엄 기능으로 포지셔닝한 앤트로픽(2024년 10월)과 오픈AI(2025년 1월)가 만든 업계 패턴을 뒤집는다. 구글의 승부수는 에이전틱 제어를 범용재로 만들면 마진 추출보다 시장이 더 빠르게 커진다는 것이다. 그러나 안전성과 처리량 사이의 구조적 긴장은 이런 에이전트가 안전하게 할 수 있는 일에 실질적인 한계를 만든다.

01"네이티브" 컴퓨터 사용이 실제로 의미하는 것

"네이티브"라는 말은 구글의 아키텍처 구분이다. Gemini 3.5 Flash 이전의 주요 컴퓨터 사용 구현 — 앤트로픽의 Claude 컴퓨터 사용(2024년 10월), 오픈AI의 CUA(2025년 1월), 구글 자체의 Gemini 2.5 Computer Use Preview(2026년 봄) — 은 모두 별도의 모델 엔드포인트나 특화된 도구 호출 스키마를 요구했다 2011. 개발자는 행동 예측 동작을 얻으려면 트래픽을 다른 모델로 라우팅해야 했다.

Gemini 3.5 Flash는 대신 개발자가 텍스트 생성, 함수 호출, 코드 실행에 쓰는 바로 그 API인 Interactions API 안에 컴퓨터 사용을 내장 도구로 탑재한다 18. 모델은 스크린샷을 이미지 입력으로 받고, 이에 대해 추론한 뒤, 구조화된 function_call 행동 이름이 담긴 응답을 출력한다(예: click_at, type_text_at)와 픽셀 좌표 5. 애플리케이션 계층은 이를 OS 수준 명령 — 마우스 클릭, 키 입력, 스크롤 — 으로 변환한 뒤, 새 스크린샷을 캡처하고 반복한다 1.

핵심 기술적 차이: 구글은 정규화된 1000x1000 좌표 공간을 사용한다 5. 원시 픽셀 좌표를 예측하는 대신(예: x=1234 을 2560px 폭 디스플레이에서), 모델은 좌표를 [0,1000) 범위로 출력하고 애플리케이션이 실제 화면 해상도에 맞게 스케일한다. 이는 행동 정밀도를 화면 해상도에서 분리해 다양한 디스플레이 크기에서 일반화를 개선할 수 있다. 반면 앤트로픽은 원시 픽셀 좌표를 쓰며, macOS가 스크린샷을 2x 해상도로 캡처하는 레티나/HiDPI 디스플레이의 기기 픽셀 비율(DPR) 문제를 명시적으로 경고한다 — 애플리케이션은 스크린샷을 다운스케일하거나 반환된 좌표를 절반으로 줄여야 한다 11.

구글의 접근은 세 가지 환경 유형 — 브라우저, 모바일(ADB를 통한 안드로이드), 데스크톱(OS 수준 커서 명령) — 을 지원한다 6 — 반면 앤트로픽의 참조 구현은 Docker/Xvfb 샌드박스와 Playwright 기반 브라우저 자동화에 초점을 둔다.

아키텍처 노트

"네이티브"라는 주장은 맥락 안에서 이해해야 한다. API 수준에서 세 제공자 모두의 애플리케이션은 클라이언트 측에서 행동을 실행한다. 모델이 행동을 예측하고, 애플리케이션이 변환해 실행한다. "네이티브"는 행동 세트가 별도로 정의된 도구가 아니라 모델 정의의 일급 요소라는 뜻이지, 실행 패턴은 아키텍처적으로 동일하다. 구글의 3.5 Flash는 레거시 함수 호출 스타일 응답과 "의도가 담긴 간소화된 명령"을 모두 지원한다 — 후자는 행동 전에 각 단계의 근거를 설명하는 reasoning 필드를 추가한다 18.

전형적인 30단계 브라우저 자동화 작업 — 단계당 입력 토큰 약 4,000(스크린샷)과 출력 토큰 2,000 — 의 스탠다드 티어 작업당 비용은 대략 $0.024이며, 배치/플렉스 티어에서는 1센트 미만이다. 무료 티어(월 5,000회 프롬프트, Gemini 3 모델 전체에 공유)는 지출 전에 상당한 프로토타이핑을 가능하게 한다 16.

전략적 신호

구글이 컴퓨터 사용을 Pro가 아닌 Flash에 탑재한 선택은 범용재화 전략을 보여 준다. 에이전틱 제어를 프리미엄 업셀이 아니라 저렴한 기본값으로 만듦으로써, 구글은 $35빌리언 달러 규모 RPA 시장(UiPath식 봇당 라이선스)을 겨냥하고 이를 종량제 토큰 호출로 전환한다 1. 이는 구글이 이메일 저장소, 지도 API, 클라우드 인프라에서 쓴 같은 플레이북이다. 위 계층을 범용재로 만들고, 아래의 유통 계층을 장악한다.

03안전성-처리량 긴장

컴퓨터 사용은 텍스트 전용 API 호출에는 없는 새로운 종류의 안전 과제를 도입한다. 화면 수준 접근을 가진 에이전트는 임의의 콘텐츠(주입된 지시 포함)를 읽고, 되돌릴 수 없는 행동(파일 삭제, 결제 제출, 자격 증명 변경)을 실행하며, 자신의 모니터링 UI를 관찰할 수 있다. 컴퓨터 사용을 위한 구글의 안전 인프라는 네 개의 뚜렷한 계층으로 구성된다.

계층 1 — 적대적 학습. Gemini 3.5 Flash는 프롬프트 주입 위험을 완화하기 위해 컴퓨터 사용에 특화된 표적 적대적 학습을 사용한다. 모델은 저항력을 기르기 위해 학습 중 주입형 공격에 의도적으로 노출된다 1.

계층 2 — 행동별 안전 분류기. 모든 function_call 응답에는 safety_decision 이 포함되며, 내부 안전 시스템이 해당 행동을 regular/allowed, require_confirmation, 또는 blocked 14으로 분류한다. 이는 실행 전 모든 행동에 동기적으로 돌아가므로, 에이전트 루프의 각 반복이 분류기의 지연을 감수한다.

계층 3 — 일곱 가지 범주 수준 안전 정책. 구글은 이름이 붙은 일곱 가지 정책 범주를 정의하며, 각각 특정 USER_CONFIRMATION 요구 사항에 대응한다 8:

FINANCIAL_TRANSACTIONS
결제 및 규제 대상 상품에 대해 차단하거나 확인을 유발한다
COMMUNICATION_TOOL
자율적인 이메일/메시지 발송을 제한한다
ACCOUNT_CREATION
자율적인 웹 계정 등록을 제한한다
LEGAL_TERMS_AND_AGREEMENTS
자율적인 이용약관 또는 계약 수락을 막는다
USER_CONSENT_MANAGEMENT
쿠키/개인정보 프롬프트에 사용자 개입을 요구한다
SENSITIVE_DATA_MODIFICATION
건강, 금융, 정부 기록을 보호한다
DATA_MODIFICATION
파일 시스템 및 저장소 변경을 규제한다

이 정책들은 세션별로 safety_policy_overrides 배열을 통해 재정의할 수 있다 — 안전성을 낮추는 문서화된 메커니즘이다(문서는 이를 "고급 옵트인"이라고 부른다) 13. 이는 본인-대리인 문제를 만든다. 프로덕션 압박을 받는 개발자가 에이전트 처리량을 높이려고 안전장치를 약화할 수 있다.

계층 4 — 옵트인 스크린샷 픽셀 스캐너. 별도의 안전 메커니즘이 스크린샷 픽셀에서 숨겨진 적대적 프롬프트 지시(예: "이전 명령을 무시하라")를 스캔하고, 탐지되면 실행을 차단한다 13. 모델 출력에 대해 동작하는 행동별 분류기와 달리, 이 스캐너는 시각 입력에 대해 동작한다.

트레이드오프 메커니즘

안전 분류기는 에이전트 루프의 모든 반복에 측정 가능한 지연을 더한다. 각 스크린샷을 스캔해야 하고, 각 행동을 분류해야 하며, 특정 행동은 진행 전 사용자 확인이 필요하다. 구글이 권장하는 시스템 지시 템플릿은 CAPTCHA 해결을 명시적으로 금지하고 "모든 법적/동의 행동"에 사용자 확인을 요구한다. 문서는 행동 품질과 실행 속도를 균형 맞추기 위한 설정 가능한 "사고 수준"을 인정한다 — 안전 오버헤드가 처리량과 경쟁한다는 직접적인 인정이다 1.

행동별 동기 분류는 시간 임계 자동화 파이프라인(예: 대시보드를 감시하고 조건 발생 후 수초 안에 행동하는 경우)에서 안전 검사가 병목이 될 수 있음을 뜻한다. 휴먼인더루프(HITL) 확인이 필요한 차단된 행동 하나가 사용자가 응답하거나 타임아웃이 발생할 때까지 전체 에이전트를 멈출 수 있다.

04AI 제어 로드맵 맥락

구글 딥마인드는 AI 제어 로드맵 을 6월 18일, 2026년에 발표했다 — 컴퓨터 사용 출시 6일 전 — 저자는 로힌 샤와 포어 플린이다 4. 이 프레임워크는 AI 에이전트를 신뢰할 수 없는 내부자 위협으로 다루고, 정렬에 기반한 신뢰가 아니라 심층 방어 완화를 써야 한다고 주장한다 4.

로드맵은 TRAIT&R (Taxonomy of Rogue AI Tactics and Routines, 불량 AI 전술 및 루틴 분류체계)를 도입한다. MITRE ATT&CK를 모델로 하며, 통제 상실, 업무 방해, 직접 피해라는 세 위협 범주를 둔다. 15개의 구체적 완화를 4개 탐지 계층(D1–D4)과 3개 예방/대응 계층(R1–R3)에 걸쳐 정의한다 4.

로드맵과 함께 나온 구글 딥마인드의 발표 트윗에는 인상적인 주장이 담겨 있었다. "우리 데이터에 따르면 문제의 대다수는 악의에서 비롯되지 않는다. 대개 에이전트가 명령을 오해하거나, 목표를 달성하려고 지나치게 열성적인 경우에 발생한다." 4

이 인용은 트위터 스레드에 나타나며, 아닌 PDF 자체에는 없다 — 전체 컴퓨터 사용 안전 아키텍처의 철학적 토대 역할을 한다. 대부분의 실패가 적대적이기보다 인식론적이라면, 올바른 방어는 더 강한 정렬 학습이 아니라 더 나은 접근 통제이다. 화면 수준 샌드박싱, 행동 수준 분류, HITL 확인 게이트, 그리고 위에서 열거한 옵트아웃 안전 정책이다.

로드맵의 프레임워크는 컴퓨터 사용 안전 스택에 직접 대응한다. 행동별 분류기는 탐지 계층 D1(읽을 수 있는 사고 사슬 모니터링)에서 동작하고, 일곱 정책 범주는 예방 계층 R1(낮은 심각도의 가역적 피해에 대한 비동기 대응)에 대응하며, 개발자 재정의 메커니즘은 R2 영역에 있다(로드맵은 이 계층에서 "충분히 높은 수준의 확신을 달성하기가 어려울 수 있다"고 경고한다) 4.

05경쟁 비교: 세 가지 아키텍처 접근

세 가지 주요 컴퓨터 사용 제품은 가격뿐 아니라 아키텍처에서 다르다.

앤트로픽 Claude — 도구 호출 기반. 모델은 행동 유형, 좌표, 선택적 텍스트가 담긴 구조화된 JSON 도구 사용 블록을 출력하고, 애플리케이션이 이를 OS 수준 연산으로 변환한다. Claude는 데스크톱을 직접 건드리지 않는다 11. 행동 세트: key(press/hold/combination), type, mouse(left_click/right_click/double_click/middle_click/triple_click), cursor_position, drag, screenshot, scroll, wait, zoom. 앤트로픽은 명시적으로 인정한다 "현재 컴퓨터 사용 지연은 사람이 AI와 상호작용할 때 일반적인 사람 주도 컴퓨터 행동에 비해 너무 느릴 수 있다" 그리고 백그라운드 사용 사례만 권장한다 12. 픽셀 좌표 환각 문제는 문서화되어 있다. "Claude는 특정 좌표를 출력할 때 실수를 하거나 환각을 일으킬 수 있다." 11

오픈AI CUA(Computer Using Agent) — 2025년 1월 발표. 모델이 JSON 도구 호출 요청을 내는 대신 픽셀 좌표 행동을 네이티브로 예측하는 통합 행동 공간을 사용한다. 아키텍처 세부 사항은 덜 투명하지만, 보고된 핵심 지표는 38.1% OSWorld(2025년 2월 평가)이다. Operator 제품은 "게이트되어 있고 느리다"고 묘사된다 12.

구글 Gemini 3.5 Flash — 정규화된 함수 호출 패턴. 1000x1000 정규화 좌표 공간을 사용해 행동 정밀도를 화면 해상도에서 분리한다. 브라우저 행동 19개 이상, 안드로이드 행동 8개, 데스크톱 명령 16개 이상을 지원한다. 핵심 차별점은 가격 티어와 모든 행동 호출에 들어가는 의도 기반 추론 필드다.

06벤치마크: 78.4% OSWorld 주장

Gemini 3.5 Flash의 컴퓨터 사용은 78.4%(OSWorld-Verified) 10을 기록한 것으로 보고된다. 이 벤치마크는 우분투 데스크톱 환경에서 대화형 컴퓨터 작업 완료를 평가한다(LibreOffice, GIMP, VS Code, Chrome 같은 실제 애플리케이션이 관련된 369개 작업). 같은 벤치마크에서 인간 성능은 72.36%이다 10.

이 주장은 검증이 필요하다. OSWorld 리더보드에는 몇 가지 구조적 한계가 있다.

자기 보고 점수. OSWorld 결과는 제출자가 독립 검증 없이 자기 보고한다 — 스프레드시트 이름이 말 그대로 self_reported_results.xlsx 10이다. 구글은 Gemini 3.5 Flash의 OSWorld 결과를 동료 심사 맥락에서 독립적으로 발표하지 않았다.

비균일 평가 조건. 단계 예산은 제출마다 15에서 200까지 다르며, 벤치마크는 구글 드라이브 관련 작업 8개를 제외할 수 있게 한다(361개로 실행, 369개 대신) 10. 78.4%라는 수치가 361개 작업을 쓰는지 369개 작업을 쓰는지는 비교 가능성에 크게 영향을 준다.

스크린샷 대 행동 평가. OSWorld에는 같은 모델에도 갈리는 결과를 내는 두 평가 모드가 있다 — 원논문의 GPT-4V는 행동 기반 지표에서 12.24%을 기록했지만 스크린샷 기반 지표에서는 5.26-7.69%에 그쳤다 10.

스캐폴드 효과가 지배한다. OSWorld 점수의 가장 큰 단일 예측 변수는 베이스 모델이 아니라 프레임워크/스캐폴드다. 원시 Claude 3.7은 약 28%이지만, Agent S2 + Claude 3.7은 34.5%다. AskUI의 독자 스캐폴드는 비슷한 베이스 모델을 써서 리더보드 선두인 66.2%를 기록한다. 구글의 78.4%이 맞춤 스캐폴드로 나온 것이라면, 이는 모델의 고유 능력이 아니라 결합 시스템(모델 + 에이전트 루프 + 행동 파싱 + 오류 복구)을 반영한다 10.

주의

여기 인용된 OSWorld 점수는 X(구 트위터)의 구글 관계자가 보고한 것이다 — 이 수치는 동료 심사 출판물에서 독립적으로 검증되지 않았다. 검증된 제3자가 표준 조건에서 결과를 재현하기 전까지, 78.4%은 확정된 사실이 아니라 상한선에 가까운 벤더 주장으로 다루어야 한다.

07테제가 깨질 수 있는 지점

"저가 티어 에이전틱 제어" 테제는 적대적 검토가 필요한 여러 가정 위에 서 있다.

가정 1: "RPA를 대체할 만큼 싸다." $35빌리언 달러 RPA 시장의 기존 강자(UiPath, Automation Anywhere, Blue Prism)는 순수 작업당 경제성만으로 가격이 매겨지지 않는다. 엔터프라이즈 RPA 구매자는 신뢰성, 감사 추적, 컴플라이언스 인증, 기존 워크플로 통합을 중시한다. OSWorld 성공률 78.4%인 LLM 에이전트 — 그리고 엔터프라이즈 특화 워크플로에서의 알려지지 않은 신뢰성 — 는 가격만으로 UiPath의 99.9% 신뢰 봇 런타임을 밀어내지 못한다. 작업당 비용($0.024)은 실패율이 감내 가능할 때만 매력적으로 보이며, 엔터프라이즈 맥락의 모든 실패(잘못된 필드 입력, 잘못된 결정)에는 복구 비용이 따른다.

가정 2: "네이티브"가 더 낫다. API 수준에서 실행 패턴은 세 제공자 모두 동일하다. 모델이 행동을 예측하고, 애플리케이션이 실행한다. "네이티브" 주장은 기술적 구분이 아니라 마케팅 구분이다. 구글은 다른 API 표면 아래에서 같은 도구 호출 메커니즘을 사용한다. 정규화 좌표 공간은 실질적 개선이지만, 에이전트 루프 신뢰성 문제를 근본적으로 바꾸지는 않는다.

가정 3: 무료 티어가 개발을 지탱한다. 무료 티어(월 5,000회 프롬프트, 모든 Gemini 3 모델)는 프로토타이핑에는 넉넉하지만 에이전틱 워크로드에서는 금방 소진된다. 스크린샷과 행동 예측을 포함한 20회 반복이 들어가는 컴퓨터 사용 작업 하나가 무료 풀에서 프롬프트 20회를 소비한다. 실제 에이전틱 소프트웨어 테스트는 무료 할당량을 하루 만에 쉽게 태운다.

가정 4: 안전 오버헤드는 무시할 만하다. 행동별 안전 분류기는 모든 단계에 동기 지연을 더한다. 일곱 가지 범주 수준 안전 정책, 픽셀 스캐너, HITL 확인 게이트가 모두 누적된다. 구글은 품질을 속도와 맞바꾸는 설정 가능한 "사고 수준"을 문서화한다 — 공짜 점심은 없다는 명시적 인정이다. 처리량이 중요한 프로덕션 에이전트 루프(예: 입력 작업 대기열을 처리하는 경우)에서 지배적 비용 요인은 토큰당 모델 비용이 아니라 안전 분류기 지연일 수 있다.

가정 5: 시장은 정확도가 아니라 물량을 원한다. 구글의 Flash 티어 승부수는 컴퓨터 사용을 싸고 쉽게 쓰면 프리미엄 에이전트당 경제성보다 시장이 더 빨리 커진다고 가정한다. 그러나 현재 엔터프라이즈 에이전트 도입을 제약하는 것은 가격이 아니라 신뢰와 신뢰성이다 — 기업들은 "에이전트가 3x만 더 싸면 더 많이 배포하겠다"고 말하지 않는다. "프로덕션 시스템을 망가뜨리지 않는 에이전트가 필요하다"고 말한다. 구글은 안전 인프라로 이에 대응하지만, 처리량-안전성 트레이드오프는 최대 안전에서 운영하면 처리량 우위가 줄어든다는 뜻이다.

08앞으로의 전망

컴퓨터 사용을 범용재로 만들려는 구글의 움직임은 전략적으로 일관된다. 텍스트, 비전, 오디오, 코드 실행, 웹 검색, 그리고 이제 화면 수준 에이전틱 제어를 하나의 API로 묶는 Gemini 3.5 Flash 플랫폼 플레이를 연장한다. 무료 티어는 마찰 없는 프로토타이핑을 가능하게 한다. 배치/플렉스 티어는 이전의 프리미엄 가격 컴퓨터 사용 제품이 결코 이루지 못한 대규모 자동화를 경제적으로 가능하게 한다.

그러나 "안전성 대 처리량 트레이드오프"는 고칠 버그가 아니라, 화면 수준 접근을 가진 에이전트의 고유 속성이다. 모든 안전 검사는 지연을 더한다. 모든 처리량 최적화는 안전 커버리지를 제거한다. 일곱 정책 범주에 대한 개발자 재정의 메커니즘이 배출 밸브이며, 프로덕션에서 그 밸브는 쓰일 것이다.

AI 제어 로드맵의 프레이밍 — "문제의 대다수는 악의에서 비롯되지 않는다" — 는 안심이 되면서도 우려스럽다. 안심인 이유는 오정렬 위험이 슈퍼얼라인먼트 돌파가 아니라 접근 통제로 관리될 수 있다는 뜻이기 때문이다. 우려인 이유는 "지나치게 열성적인" 에이전트가 화면 수준 접근으로 좋은 의도를 가지고도 실제 피해를 낼 수 있기 때문이며 — 집행 메커니즘은 API를 쓰는 모든 개발자가 우회할 유인을 갖는 안전 분류기의 지연이다.

엔터프라이즈 도입자에게 결정적인 질문은 "충분히 싼가?"가 아니라 "어느 오류율에서 싼 것이 비싸지는가?"다. 현재 상한이 가격이 아니라 신뢰성으로 정의되는 시장에서, Gemini 3.5 Flash의 네이티브 컴퓨터 사용은 공략 가능한 표면을 넓히지만, 처리량-안전성 트레이드오프가 실질적 상한을 규정한다.
