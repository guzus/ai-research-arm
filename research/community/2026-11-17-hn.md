- How the Claude Code team thinks about verification: New, and the largest new AI comment thread. 71 points / 90 comments. claude.dev/blog/how-the-claude-code-team-thinks-about-verification/ (Addy Osmani, 2026-11-16; Anthropic engineering blog, not an independent eval). Stamps that ~90% of the Claude Code team's code is written and reviewed by Claude. Internal testing around structured file generation: a separate grader checking Claude's work against a rubric improved task success by up to 10 points over a standard prompting loop, largest gains on the hardest problems. Three test types named as worth investing in: end-to-end (real user flows; "difficult to fool"); property tests (fast-check / Hypothesis / proptest generating thousands of inputs against round-trip, invariant, idempotency, and equivalence claims); differential tests (old system as oracle on random inputs or a sample of production traffic, with a list of approved differences). Team practice on that page: a `verify` skill under `.claude/skills/` so Claude smoke-tests the running app (Chrome extension for web, iOS/Android MCP for mobile, computer use for desktop, or a local service for backend) before committing; failing checks get three agent-fix rounds then a human; code owners write the checks; a 39-item reliability checklist, each with a diff-readable trigger, so Claude usually runs 3–10 items rather than the whole list (example: "--resume loads old transcripts" when session storage or message types change). One reviewer, multiple rounds, with a `REVIEW.md` of what to watch for this code; Code Review reads `REVIEW.md` from the base/default branch, never from the PR, so a change cannot rewrite the check that judges it. Reviews are reserved for commits (a passing review on an out-of-date commit means nothing). Cheap checks first: Claude runs tests, build, and linter before opening a PR. Each commit is stamped with how it was verified, including `"none"`. A commit gate can require `/code-review` or `/verify` in the session — modes `off` / `observe` / `enforce`; after two blocked commits the next one is allowed through so Claude does not get stuck. Flaky tests: Claude cannot skip them, add sleeps, or retry until they pass; if it cannot find the root cause it deletes the test and writes down why. They also evaluate the reviewers (reverts, maintainer rejections, a size-matched clean subset) and split recall across raw findings, post-verification, and final review so a bug the system already found is not lost later. - https://news.ycombinator.com/item?id=50529612
